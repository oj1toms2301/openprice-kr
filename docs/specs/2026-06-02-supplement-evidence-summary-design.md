# 영양제 리포트 공개 요약 설계

## 목적

`openprice-kr`의 영양제 리포트는 가격만 비교하지 않는다.

사용자가 실제로 궁금해하는 것은 다음에 가깝다.

- 이 제품이 얼마인가
- 1정 또는 1캡슐당 얼마인가
- 하루 복용량 기준으로 하루에 얼마인가
- 성분의 효능 근거가 어느 정도인가
- 국내 건강기능식품 기능성 원료로 인정되었는가

따라서 이 프로젝트는 영양제 가격 비교와 간단한 효능/근거 요약을 함께 제공하는 방향으로 확장한다.

이 문서는 공개 저장소에 포함할 수 있는 리포트 구조와 표현 원칙만 다룬다.

## 기본 방향

리포트는 다음 정보를 한 HTML에서 보여준다.

- 가격 후보
- 배송비 포함 최종가
- 단위당 가격
- 하루 복용량 기준 비용
- 간단한 성분 요약
- 국내 기능성 원료 인정 여부
- 효능/근거 요약
- 주의사항
- 후기에서 자주 보이는 반응

초기 구현은 `잔티젠` 1개 성분을 기준으로 작게 검증한다.

## 공개 HTML 리포트의 역할

공개 HTML 리포트는 외부 상세 문서 없이도 기본 판단이 가능해야 한다.

공개 리포트에 포함할 수 있는 정보:

- 성분명
- 가격 비교 후보
- 제품별 총량
- 1정, 1캡슐, 1포 등 단위당 가격
- 하루 복용량
- 하루 비용
- 국내 기능성 원료 인정 여부
- 대표 효능 주장
- 효능별 간단한 근거 등급
- 짧은 효능/근거 요약
- 핵심 주의사항
- 최소한의 참고자료

공개 요약은 너무 빈약하면 안 된다. GitHub 소스만 사용하는 사람도 어느 정도 근거가 포함된 HTML을 생성할 수 있어야 한다.

## 데이터 구조 방향

공개 요약 데이터는 성분 단위와 제품 단위를 분리한다.

성분 단위 데이터는 성분 자체에 대한 정보를 담는다.

예시:

```json
{
  "ingredientId": "xanthigen",
  "nameKo": "잔티젠",
  "functionalIngredientStatus": "needs_review",
  "functionalIngredientStatusLabel": "확인 필요",
  "claims": [
    {
      "claim": "체지방 감소 관련",
      "evidenceLevel": "검토 필요",
      "summary": "초기 공개 요약에서는 핵심 근거와 한계를 짧게 설명한다."
    }
  ],
  "cautions": [
    "임신, 수유, 질환 치료 중인 경우 전문가 상담이 필요할 수 있다."
  ],
  "references": []
}
```

제품 단위 데이터는 가격과 복용 비용 계산에 필요한 정보를 담는다.

예시:

```json
{
  "productName": "샘플 잔티젠 제품",
  "unitType": "캡슐",
  "unitCount": 60,
  "dailyServingCount": 2,
  "totalPrice": 30000,
  "unitPrice": 500,
  "dailyCost": 1000,
  "daysCovered": 30
}
```

## 국내 기능성 원료 인정 여부

국내 기능성 원료 인정 여부는 단순 문장이 아니라 상태값으로 관리한다.

가능한 상태:

- `recognized`: 인정됨
- `not_recognized`: 인정되지 않음
- `needs_review`: 확인 필요
- `unknown`: 아직 조사하지 않음

초기 샘플에서 공식 확인이 끝나지 않은 항목은 `needs_review`로 둔다.

## 후기에서 자주 보이는 반응

쇼핑몰 리뷰는 효능 근거로 보지 않는다.

하지만 특이한 영양제나 잘 알려지지 않은 성분에서는 사람들이 어떤 기대를 가지고 구매했는지, 실제 후기에서 어떤 이야기가 반복되는지 참고자료가 될 수 있다.

이 항목의 이름은 `후기에서 자주 보이는 반응`으로 둔다.

피해야 할 표현:

- 리뷰 근거
- 소비자 체감 신호
- 실제 효능 후기
- 효과 입증 후기

권장 표현:

- 후기에서 자주 보이는 반응
- 후기에서 반복되는 이야기
- 구매자 후기 요약

공개 HTML에서는 짧게만 보여준다.

예시:

```text
후기에서 자주 보이는 반응

일부 후기는 복용 편의성, 체지방 감소 기대, 속 불편함 여부를 자주 언급합니다.
후기는 개인 경험이므로 효능 근거로 해석하지 않습니다.
```

후기 자료는 효능/근거 요약과 명확히 분리해서 표시한다.

공개 저장소에는 원문 리뷰를 길게 싣지 않는다. 닉네임, 사진, 개인 식별 가능 정보도 저장하지 않는다.

초기 단계에서는 자동 대량 크롤링을 하지 않는다. 사용자가 직접 제공한 URL, 허가된 데이터, 또는 샘플 리뷰로 먼저 검증한다.

## 외부 상세 링크 노출 원칙

공개 HTML 리포트에는 외부 상세 링크를 기본 노출하지 않는다.

이유:

- 오픈소스 도구가 특정 사이트 유입용으로 보일 수 있다.
- 근거 요약이 일부러 짧게 작성된 것처럼 보일 수 있다.
- 리포트 자체의 독립성이 약해질 수 있다.

따라서 기본값은 다음과 같다.

```json
{
  "showExternalDetailLinks": false
}
```

사용자가 직접 켠 경우에만 HTML 하단에 중립적으로 표시한다.

예시:

```text
추가 해설: 외부 상세 문서
```

이 링크는 버튼처럼 강조하지 않는다. 가격 비교 표나 근거 요약의 핵심 위치에도 두지 않는다.

## 표현 원칙

영양제 효능 표현은 조심스럽게 작성한다.

피해야 할 표현:

- 치료된다
- 확실히 효과가 있다
- 누구에게나 추천한다
- 먹으면 살이 빠진다

권장 표현:

- 일부 연구에서 관찰되었다
- 근거 수준은 제한적이다
- 국내 기능성 인정 여부는 별도로 확인이 필요하다
- 개인의 건강 상태에 따라 전문가 상담이 필요할 수 있다

이 프로젝트는 의료 조언을 제공하지 않는다. 가격 비교와 근거 요약을 돕는 정보 도구로 본다.

## 첫 구현 범위

처음에는 한 성분으로 전체 흐름을 작게 검증한다.

첫 구현 범위:

1. `잔티젠` 1개 성분의 공개 요약 샘플을 만든다.
2. 가격 후보 HTML에 성분 요약 영역을 추가한다.
3. 제품별 1정 또는 1캡슐당 가격을 표시한다.
4. 하루 복용량 기준 비용을 표시한다.
5. 국내 기능성 원료 인정 여부를 표시한다.
6. 후기에서 자주 보이는 반응을 효능 근거와 분리해서 표시한다.
7. 사용자가 생성된 HTML을 직접 검토한 뒤 다음 공개 작업을 결정한다.

## 성공 기준

첫 확장 단계의 성공 기준은 다음과 같다.

- 공개 HTML 리포트에 가격 비교와 간단한 효능/근거 요약이 함께 나온다.
- 1정 또는 1캡슐당 가격, 하루 복용량, 하루 비용이 표시된다.
- 국내 기능성 원료 인정 여부가 표시된다.
- 외부 상세 링크는 기본 HTML에 노출되지 않는다.
- 후기 정보가 들어가더라도 효능 근거와 명확히 분리되어 표시된다.
- 사용자가 HTML 결과물을 직접 보고 검토한 뒤에만 다음 공개 작업을 진행한다.

## 아직 하지 않는 것

이번 설계에서 바로 하지 않는 것:

- 대규모 쇼핑몰 자동 크롤링
- 여러 성분의 전체 데이터 공개
- 의학적 효능 판정 자동화
- LLM 결과의 무검토 자동 공개
- 제휴 링크 자동 삽입
- 쇼핑몰 리뷰 자동 대량 크롤링

초기 목표는 작게 검증 가능한 리포트 흐름을 만드는 것이다.
