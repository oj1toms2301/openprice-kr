# 잔티젠 가격 후보 탐색 리포트 MVP 설계

## 목적

첫 MVP는 `잔티젠`을 기준 상품으로 고정하고, 여러 쇼핑몰에서 온 가격 후보를 한곳에서 비교하는 흐름을 보여준다.

쉬운 말:

- 사용자가 여러 쇼핑몰을 직접 돌아다니지 않아도 된다.
- 가능한 다양한 가격 후보를 한 리포트에서 본다.
- 같은 제품으로 보이는 후보는 묶어서 가장 저렴한 대표 후보를 먼저 본다.
- 상품 이미지와 링크를 함께 보여줘서 사람이 직접 검토할 수 있다.

개발자 용어:

- 여러 출처 상품 탐색: multi-source product discovery
- 중복 상품 묶기: product deduplication
- 최저가 대표 선택: best offer selection
- 사람이 검토하는 매칭: human-in-the-loop matching
- 정적 HTML 리포트: static HTML report

## 핵심 문제

일반 검색 도구나 일부 가격 비교 서비스는 다음 한계를 가질 수 있다.

- 특정 쇼핑몰이나 브랜드몰의 더 저렴한 상품을 놓칠 수 있다.
- 모바일 최적화 페이지, 회원 전용 가격, 검색 노출 방식 차이 때문에 후보가 누락될 수 있다.
- 같은 제품이 여러 쇼핑몰에 흩어져 있어 소비자가 직접 비교해야 한다.
- 상품명만으로는 같은 제품인지 판단하기 어렵다.
- 링크가 정확하지 않으면 실제 구매 후보로 활용하기 어렵다.

이 MVP는 실제 외부 사이트 자동 수집을 바로 구현하지 않고, 샘플 데이터로 이 문제 구조를 먼저 보여준다.

## 첫 MVP 범위

이번 MVP에서 할 일:

- 기준 상품을 `잔티젠`으로 고정한다.
- 여러 출처에서 온 것처럼 구성한 샘플 후보 데이터를 만든다.
- 후보마다 상품명, 쇼핑몰명, 가격, 배송비, 최종가, 링크, 이미지 정보를 가진다.
- 같은 제품으로 볼 수 있는 후보를 묶는다.
- 묶인 후보 중 배송비 포함 최종가가 가장 낮은 후보를 대표로 표시한다.
- 같은 제품인지 애매한 후보는 `검토 필요`로 표시한다.
- 결과를 사람이 읽기 좋은 HTML 리포트로 만든다.

이번 MVP에서 하지 않는 것:

- 실제 쇼핑몰 크롤링
- 로그인 뒤 가격 수집
- 실시간 최저가 보장
- 결제, 주문, 회원 기능
- 이미지 AI 모델 연동
- 웹 서버 운영
- 데이터베이스 사용

## 데이터 구조 방향

샘플 데이터는 실제 수집 데이터가 아니라 검증용 예시 데이터다.

각 가격 후보는 다음 정보를 가진다.

- `id`: 후보 고유 ID
- `query`: 검색어, 예: `잔티젠`
- `source`: 출처 이름, 예: 쿠팡, 네이버쇼핑, 다나와, 브랜드몰, 개별 쇼핑몰
- `productName`: 쇼핑몰에 표시된 상품명
- `brand`: 브랜드명
- `price`: 상품 가격
- `shippingFee`: 배송비
- `totalPrice`: 배송비 포함 최종 가격
- `currency`: 통화, 예: `KRW`
- `url`: 상품 상세 페이지 링크
- `imageUrl`: 상품 이미지 링크 또는 로컬 이미지 자리
- `packageSize`: 용량, 캡슐 수, 포장 단위 등
- `groupKey`: 같은 제품으로 묶기 위한 기준값
- `matchConfidence`: 같은 제품으로 볼 수 있는 신뢰도
- `matchReason`: 묶은 이유
- `needsReview`: 사람이 확인해야 하는지 여부

## 같은 제품 묶기 방향

첫 MVP의 중복 묶기는 완전 자동 판별이 아니라 규칙 기반으로 시작한다.

쉬운 말:

- 브랜드명, 용량, 캡슐 수, 상품명 키워드가 비슷하면 같은 제품 후보로 묶는다.
- 이미지가 있으면 HTML 리포트에서 나란히 보여줘 사람이 확인할 수 있게 한다.
- 애매하면 자동으로 확정하지 않고 `검토 필요`로 남긴다.

개발자 용어:

- 규칙 기반 매칭: rule-based matching
- 이미지 기반 매칭 준비: image-aware matching fields
- 사람 검토 포함 매칭: human-in-the-loop deduplication

이미지 인식은 중요한 방향이지만 첫 MVP에서는 실제 모델을 붙이지 않는다.

대신 다음을 준비한다.

- `imageUrl` 필드를 둔다.
- 리포트에서 이미지 썸네일을 보여준다.
- `matchConfidence`와 `needsReview`로 자동 판단과 사람 검토를 구분한다.
- 나중에 이미지 인식 모델이나 GPT 비전 기능을 붙일 수 있게 데이터 구조를 열어둔다.

## 리포트 화면 방향

HTML 리포트는 소비자가 빠르게 판단할 수 있어야 한다.

리포트에 보여줄 내용:

- 검색어: `잔티젠`
- 리포트 생성 시각
- 샘플 데이터 기반이라는 안내
- 제품 그룹별 대표 최저가 후보
- 같은 제품으로 묶인 다른 후보 목록
- 상품 이미지
- 쇼핑몰명
- 상품명
- 상품 가격
- 배송비
- 배송비 포함 최종가
- 상품 링크
- 매칭 신뢰도
- 검토 필요 표시

표현 원칙:

- 같은 제품 그룹에서는 최저가 대표 후보를 맨 위에 둔다.
- 링크는 실제 후보를 확인할 수 있도록 눈에 잘 보이게 둔다.
- 애매한 후보는 싸더라도 무조건 확정하지 않고 검토 필요로 표시한다.
- 샘플 데이터라는 점을 리포트 상단에 명확히 쓴다.

## Codex Skill 방향

이 프로젝트는 단순 프롬프트 모음이 아니라 Codex 앱에서 실행 가능한 작업 흐름을 목표로 한다.

첫 Skill은 다음 역할을 가진다.

- 사용자가 검색어와 후보 데이터를 준비하도록 안내한다.
- 실제 크롤링 전에 데이터 안전 원칙을 확인하게 한다.
- 샘플 데이터로 리포트를 생성하는 명령을 안내한다.
- 결과 HTML을 검토하고, 같은 제품 묶기가 이상한 후보를 찾게 한다.

쉬운 말:

- Codex가 사용자를 도와 가격 후보를 정리하고 리포트를 만들게 하는 사용 설명서다.

개발자 용어:

- Codex Skill workflow
- local report generation workflow
- review-oriented data normalization

## 기술 선택

첫 구현은 npm 패키지 없는 Node.js 스크립트로 만든다.

선택 이유:

- HTML 파일 생성에 적합하다.
- Codex 앱과 로컬 작업 흐름에 잘 맞는다.
- `npm install` 없이 실행할 수 있어 공급망 위험이 낮다.
- Windows 환경에서도 Node.js만 있으면 시작하기 쉽다.

개발자 용어:

- zero-dependency Node.js script
- static report generator

## 성공 기준

이번 MVP는 다음 조건을 만족하면 성공이다.

- `잔티젠` 샘플 후보 데이터가 있다.
- HTML 리포트를 생성할 수 있다.
- 같은 제품 후보가 그룹으로 묶여 보인다.
- 각 그룹에서 배송비 포함 최저가 대표 후보가 보인다.
- 상품 이미지와 링크가 함께 보인다.
- 애매한 후보는 `검토 필요`로 표시된다.
- 실제 크롤링이 아니라 샘플 기반 검증이라는 점이 명확하다.
- Codex Skill 문서가 사용 흐름을 안내한다.

## 나중에 확장할 것

후속 단계에서 검토할 수 있는 일:

- 쿠팡, 네이버쇼핑, 다나와, 개별 쇼핑몰별 검색 어댑터
- 공개 API 연동
- 사용자가 제공한 URL 기반 후보 추가
- 이미지 인식 기반 상품 매칭
- GPT 비전 기능을 활용한 상품 이미지 비교
- 가격 이력 저장
- 알림 기능
- 더 많은 영양제 카테고리 지원

## 안전 원칙

이번 MVP는 실제 쇼핑몰을 자동 수집하지 않는다.

외부 사이트와 연결하기 전에는 다음을 먼저 검토한다.

- 서비스 약관
- `robots.txt`
- 공개 API 제공 여부
- 로그인/회원 전용 가격 처리 가능 여부
- 요청 빈도 제한
- 데이터 재사용과 출처 표시 조건

이 문서는 개발 방향을 정리한 것이며 법률 자문이 아니다.
